# LARP Studio — браузерная мастерская

**Открыть мастерскую: https://mgoutside16-spec.github.io/larp/**

Основной вариант — сайт по постоянной ссылке. Пользователю нужен только браузер.
Python, Node.js, установщик и локальный сервер на его компьютере не нужны.

## Вход и личный кабинет

Зарегистрируйте аккаунт с почтой и паролем и подтвердите почту по ссылке из письма.
Войдите на сайт. Сначала назначенный администратор — `mgoutside16@gmail.com`;
права назначаются только после настоящего подтверждения этой почты.

Администратор видит все проекты и раздел пользователей. Мастер видит свои
проекты и проекты, куда его добавили. Владелец или администратор добавляет коллегу
по почте в «Участниках проекта». Для ещё не зарегистрированного пользователя
сохраняется приглашение; его можно отменить. После регистрации и подтверждения
почты приглашённый получает доступ. Участники редактируют проект совместно.

Изменения разных записей объединяются. При одновременном изменении одной записи
второй редактор получает предупреждение, его несохранённый текст остаётся в окне.
Права проверяются RLS базы и серверными функциями, а не скрытием кнопок.

## Работа с играми

1. Создайте проект и группы видений — например «Сны» и «ЭП».
2. Создайте записи с текстом, фото, аудио и видео. Код выдаётся автоматически и
   сохраняется при изменениях. Используйте предпросмотр и порядок блоков.
3. В «Кодах и печати» загрузите изображение одной карточки или откройте готовый
   пример «Сновидение» из предоставленного PDF. Выберите группу, перетащите код,
   задайте размер, цвет и шрифт. Сохраните шаблон группы.
4. Скачайте ZIP: внутри отдельные PNG с кодами в исходном разрешении и 300 dpi.
   По одному шаблону можно выгрузить до 500 карточек; есть ограничение памяти.
   Также остаются выгрузки Excel и обычный PDF A4.
5. Создайте `.rpgpack` для игрока или резервной копии материалов. Оформление
   мастерских карточек хранится отдельно в облачном проекте аккаунта.

Проекты, медиа и шаблоны находятся в Supabase и доступны с других компьютеров.
IndexedDB — кеш, разделённый по аккаунтам; при выходе он очищается. Старое
локальное хранилище предыдущей версии не удаляется. Администратор может явно
перенести старые проекты в аккаунт через «Перенести прежние проекты»; исходные
копии сохраняются. Старые локации показываются как группы, коды не меняются.

Для облачного сохранения нужен интернет. Квоты и максимальный размер файлов
зависят от тарифа Supabase (на бесплатном тарифе обычно 50 МиБ на файл).
## Приложение игрока Android

**[Скачать APK](https://github.com/mgoutside16-spec/larp/releases/latest/download/LARP-Player.apk)**

В приложении нет регистрации: игрок импортирует `.rpgpack` либо добавляет игру
по ссылке мастера. Коды, текст, фото, аудио, видео и история работают без сети.
Три неверных кода подряд блокируют ввод на 30 минут; история остаётся доступной.
Обновления игры через файл и онлайн сохраняют коды, историю и блокировку.

Для публикации онлайн-обновлений владелец/администратор в «Сборках и версиях»
нажимает «Опубликовать обновление» и передаёт игрокам ссылку. Перед первым
использованием нужно выполнить `backend/player-updates.sql` в SQL Editor Supabase.
Он добавляет отдельное приватное хранилище публикаций; аккаунты и проекты остаются.

[Инструкция игрока и разработчика](mobile/README.md),
[контракт сервера обновлений](backend/PLAYER-UPDATES.md).

## Настройка Supabase для разработчика

`web/public/config.json` содержит только публичный URL и Publishable key.
Секретный service_role/Secret key в браузер помещать нельзя. База создаётся
`backend/schema.sql` в SQL Editor. Уже настроенная первая версия обновляется
`backend/account-update.sql`. Миграции повторяемы; реальные проекты сохраняются.
В Authentication → URL Configuration Site URL указывает на адрес мастерской.
Подтверждение почты включено. SMTP/платные ресурсы автоматически не настраиваются.

Серверные политики проверяются настоящим PostgreSQL 17: `backend/test-bootstrap.sql`
используется только в изолированной тестовой базе, затем schema.sql и
`backend/test-policies.sql`. Не запускайте test-bootstrap.sql в рабочем Supabase.
`first-admin.sql` — дополнительный ручной путь восстановления админских прав.

## Обновления через Codex

Исходники находятся в `web/`. Публикация из ветки `main` выполняется workflow
`.github/workflows/pages.yml`: Node tests, сборка, браузерные сценарии и GitHub Pages.
Перед публикацией проверяется сохранение существующих игр после замены JS-кода.
Сохраняйте права доступа и серверные версии проектов. Кеш аккаунтов можно
пересоздать; исходное локальное хранилище `larp-studio` удалять нельзя без явного
переноса пользовательских данных.

Первое включение Pages требует соответствующего права GitHub. Если оно закрыто
для подключённой интеграции, владелец репозитория включает Settings → Pages →
Source: GitHub Actions один раз. Это действие в GitHub, не установка программы.

## Для разработки в облачной среде

Это команды для Codex/разработчика; пользователь сайта их не выполняет.

```bash
cd web
npm ci
npm test
npm run build
npm run dev -- --port 5173
```

Нужен Node.js 22+ (в текущей среде 24). Playwright-проверки выполняются против
собранного `web/dist` на внутреннем тестовом HTTP-сервере:

```bash
python3 -m http.server 5173 --bind 127.0.0.1 --directory web/dist
# В другой сессии:
python3 web/tests/browser_check.py
python3 web/tests/regression_check.py
python3 web/tests/account_check.py
python3 web/tests/review_regressions.py
```

Используется системный Chromium или браузер, установленный Playwright. В CI все
инструменты устанавливаются автоматически. Локальные адреса не являются ссылкой
на опубликованный сайт.

## Форматы и ограничения

Сохраняется совместимость `.rpgpack` v1 с Python-мастерской. Браузерная версия
отклоняет архивы больше 1 ГиБ после распаковки, файлы больше 512 МиБ, manifest
больше 16 МиБ и ZIP64. Экспорт проверяет эти же ограничения до фиксации версии.
Числа должны точно представляться в JavaScript (safe integer). Облачные файлы
дополнительно ограничиваются тарифом Supabase, кеш — квотой браузера. Эти ограничения указаны для
надёжной обработки больших медиа в памяти, а не для ограничения числа блоков.

Поддержка аудио/видео зависит от браузерных кодеков. Для обмена рекомендуются
PNG/JPEG, MP3/WAV и MP4 H.264/AAC. Текст допускает базовое форматирование;
внешние ресурсы и активный HTML удаляются при показе.
