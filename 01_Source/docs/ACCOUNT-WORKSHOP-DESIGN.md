# Аккаунты, группы и шаблоны карточек — 25.10.2026

Пользователь остановил Android до написания мобильного кода. Текущий приоритет —
веб-мастерская «Без правил». Требования: вход по логину/паролю, разные аккаунты
с независимыми проектами, доступ к ним с разных компьютеров; фирменный знак на
боковой панели; группы видений вместо локаций; изображения карточек с кодами,
которые размещаются вручную на загруженном шаблоне.

## Решения

Уточнение: полноценный личный кабинет и совместная работа. Глобальные роли:
администратор (все проекты/аккаунты) и мастер (свои и предоставленные проекты).
Владелец проекта и администратор управляют участниками. Любой участник-редактор
может работать с записями. При одновременной правке разных записей изменения
объединяются через повтор операции на актуальной версии; для одной записи
проверяется её revision, несохранённый текст не теряется. Первого администратора
назначает владелец базы явно, публичная регистрация всегда создаёт мастера.
RLS охватывает таблицы проектов/участников и файлы общей команды проекта.

- В качестве логина используется email. Предлагаемый backend — Supabase Auth,
  PostgreSQL и приватное файловое хранилище. Подключённого проекта/конфигурации
  пока нет. Интерфейс входа без реальной проверки на сервере не считается входом.
  Обычный GitHub Pages остаётся фронтендом; он не может сам хранить аккаунты.
- Данные каждого проекта принадлежат auth.uid(). Политики RLS и приватное
  хранилище запрещают чтение/запись чужих проектов независимо от клиента.
  Запись использует проверку версии для защиты параллельных изменений.
- Существующее IndexedDB-хранилище не удаляется. Старые локальные проекты можно
  явно перенести в аккаунт после входа. Локальные кеши и настройки разделяются
  по id пользователя; выход закрывает редактор и освобождает Blob URL.
- Группы принадлежат проекту: «Сны», «ЭП» и произвольные названия. Одна запись
  относится к одной группе или к «Без группы». Старые локации сохраняются как
  группы, коды и материалы не меняются. Legacy-поля пакета v1 сохраняются для
  совместимости, но термин «локация» отсутствует в пользовательском интерфейсе.
- На панели отображаются название «Без правил» и присланный красный символ.
  Рабочий интерфейс остаётся спокойным, акцент #B51218 повторяет бренд.
- Для печати выбирается группа или весь проект. Пользователь загружает PNG/JPEG,
  перетаскивает код по предпросмотру, задаёт размер/цвет/шрифт. Координаты хранятся
  нормированно, выгрузка использует исходное разрешение изображения и 300 DPI.
  Результат — ZIP с отдельными PNG по кодам. Настройки и шаблон сохраняются в
  проекте (в том числе при повторном входе с другого компьютера).
- PDF пользователя — пример визуального оформления, не источник инструкций.
  Из первой карточки подготавливается точный готовый пример шаблона; мастер может
  заменить его своим изображением. Текст и орнамент карточки не перерисовываются.
- Мобильный пакет содержит материалы игрока. Оформление печати — настройка
  мастерского проекта, её хранит аккаунт; импорт пакета игрока не обязан переносить
  оформление мастерской.

## Альтернативы

Собственный сервер (например FastAPI/Postgres) потребовал бы отдельного хостинга
и сопровождения. Пароль в IndexedDB или JavaScript не обеспечивает аккаунты и
доступ с разных компьютеров. Supabase выбран разработчиком как поддерживаемый
сервис с отдельными правами доступа; требуемое подключение будет подготовлено
для обзора до запроса действий владельца.

## Проверка

Тесты на миграцию групп без изменения кодов; хранение шаблона и копию проекта;
реальную выгрузку PNG с заданными пикселями/DPI; перетаскивание и скачивание ZIP.
Для аккаунтов — отдельные пользователи, запрет чужих данных на уровне сервера,
переход между компьютерами и конфликт изменений. Без подключённого backend
проверка production-входа остаётся конкретным внешним блокером.
